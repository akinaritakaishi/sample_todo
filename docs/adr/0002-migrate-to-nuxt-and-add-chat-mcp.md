# ADR 0002: front/をNuxt(Vue)へ移行し、チャットツールとMCPサーバーを追加する

- ステータス: 承認
- 日付: 2026-09-13

## コンテキスト

これまで`front/`はReact 18 + Viteによる、ルーティングなし・バックエンドなし・永続化はブラウザの`localStorage`のみのシングルページアプリだった。今回、サンプルとして次の3点を追加したいという要望があった。

1. 簡易的なチャットツール画面
2. サーバーとAPI通信できる構成（Nuxtまたは Next.js）
3. MCPサーバーからチャットツールのデータを読み書きできること

チャットのメッセージやMCPサーバーからの書き込みをクライアントの`localStorage`だけで扱うのは筋が悪く（MCPサーバーはNode.jsプロセスとして動くため、ブラウザの`localStorage`に直接アクセスできない）、サーバー側にAPIと永続化層を持つ構成への転換が前提となる決定だった。

## 決定

- フレームワークはNuxt(Vue)を採用する。Next.js(React)も選択肢に挙がったが、ユーザーの意向によりNuxtに決定した。
- `front/`を丸ごとNuxtプロジェクトとして作り直す（Vite+React版は廃止）。既存のToDo機能（追加・完了切替・削除・完了済み一括削除）はVueコンポーネント + Nuxtの`server/api`経由で再実装する。
- チャットツールは同一Nuxtプロジェクト内の別ページ（`/chat`）として実装し、ToDo画面とはナビゲーションで行き来する。
- 永続化は本格的なDBを導入せず、Nuxtサーバープロセス内でサーバー側JSONファイル（`front/.data/`配下、gitignore対象）に保存する方式にする。タスク・チャットメッセージともに同じ方式。
- MCPサーバーはリポジトリ直下に`mcp-server/`として独立させ、`@modelcontextprotocol/sdk`を使ってstdioで待ち受ける。チャットのデータストアには直接触れず、Nuxtサーバーが提供するHTTP API（`/api/chat/messages`のGET/POST）を叩くことで読み書きする。ツールは`list_chat_messages`（読み取り）と`send_chat_message`（書き込み）の両方を提供する。

## 検討した代替案

- **Next.js(React)への移行**: 既存のReactコードをほぼそのまま移植できるため移行コストは低いが、ユーザーがNuxtを希望したため採用しなかった。
- **チャット・タスクデータをSQLiteなどの軽量DBに保存する**: より本格的な永続化になるが、ORMやマイグレーションなど構成が増え、デモ用サンプルとしての手軽さを損なう。まずはJSONファイルで十分と判断した。
- **MCPサーバーがJSONファイルを直接読み書きする**: Nuxtサーバーを経由せずファイルへ直接アクセスする案もあったが、書き込み経路が2つに分かれると競合・整合性の考慮が増える。HTTP API経由に一本化し、データアクセスの窓口をNuxtサーバーに閉じることにした。
- **front/はVite+Reactのまま残し、チャットツールだけ別プロジェクトで新規構築する**: 移行リスクは減るが、リポジトリ内に前提の異なるフロントエンドが2つ並立し、`CLAUDE.md`のアーキテクチャ説明も複雑になる。ユーザーの意向（同一プロジェクトへの統合）に従い採用しなかった。

## 結果・影響

- `front/`のスタックがReact + ViteからVue + Nuxtに変わり、`.claude/rules/front-code-style.md`などReact前提だった規約は今後Vue向けに見直しが必要になる。
- 永続化がクライアントの`localStorage`からサーバー側JSONファイルに変わったため、「サーバーは存在せず永続化はすべてクライアント側」という`docs/Architecture.md`の前提が変わる。複数タブ・複数ブラウザから同じデータを参照できるようになる一方、サーバープロセスを再起動してもファイルが残る限りデータは保持される（ファイルを消せばシードデータにフォールバックする）。
- MCPサーバーを起動するには、先にNuxtサーバー（`front/`）を起動しておく必要がある（`CHAT_API_BASE_URL`環境変数でアクセス先を変更可能、デフォルトは`http://localhost:3000`）。
- `npm test`が存在しない前提だった`CLAUDE.md`の記述は変わらないが、コマンド実行先が`front/`と`mcp-server/`の2箇所に分かれる。
