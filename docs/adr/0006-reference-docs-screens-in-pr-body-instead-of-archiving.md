# ADR 0006: PR本文のスクリーンショットはdocs/screens/を参照する方式にする（PRごとのアーカイブは廃止）

- ステータス: 承認
- 日付: 2026-09-13

## コンテキスト

ADR 0003で、UIに影響する変更を含むPRでは`docs/pr-screenshots/pr-<PR番号>/`にスクリーンショットを保存し、PR本文に埋め込む運用を決めた。その後ADR 0004で、画面ごとの「現在の仕様」を記録する`docs/screens/<画面名>.md`（と埋め込み画像`docs/screens/<画面名>.png`）を新設した。

実際にPR #16で両方を運用したところ、同じスクリーンショットを`docs/pr-screenshots/pr-16/`と`docs/screens/`の2箇所に重複して保存する結果になった。ユーザーから「`docs/pr-screenshots/pr-16/`は消してよいのでは」という指摘があり、検討の結果、次の2点が分かった。

- `docs/screens/`が「現在の画面はこうである」を常にカバーするなら、PRごとに別途アーカイブを残す必要性は薄い。
- 一方で、GitHubのPR本文（Issue/PR description）に書いた相対パスの画像リンクは、そのPRのブランチではなくリポジトリの**デフォルトブランチ**を基準に解決される。そのため、PRの説明文にそのPR自身が追加したファイルへの相対リンクを書いても、マージされるまでは正しく表示されない（あるいはマージ後にファイルを消せば、その時点で恒久的にリンク切れになる）という制約がある。

## 決定

- `docs/pr-screenshots/`（PRごとのスクリーンショットアーカイブ）という運用は廃止する。既存の`docs/pr-screenshots/pr-16/`は削除する。
- UIに影響する変更を含むPRでは、`docs/screens/<画面名>.png`（ADR 0004で新設した、画面変更のたびに上書きする「現在の仕様」用スクリーンショット）を、そのままPR本文（「テスト内容」セクション）にMarkdown画像として埋め込む。
- 「UIに影響する変更ではPR本文にスクリーンショットを埋め込むことを必須にする」というADR 0003の方針自体は変更しない。変わるのは画像の保存場所・参照先だけである。
- 上記のGitHubの相対リンク解決の制約により、画像がマージ前のPR本文プレビューで正しく表示されない場合があることを許容する（マージ後は`docs/screens/`がデフォルトブランチ上に存在するため表示される）。手順は`.claude/skills/commit-and-pr/SKILL.md`（5.1節）に反映する。

## 検討した代替案

- **`docs/pr-screenshots/`をそのまま維持する（ADR 0003のまま）**: PRごとに「レビュー当時どう見えたか」を正確に記録できる利点はあるが、`docs/screens/`と内容が重複し、画面が変わるたびに増え続ける（このデモ用リポジトリでは許容範囲だが、`docs/screens/`という「現在の仕様」の置き場を作った以上、二重管理する理由が薄いと判断した）。
- **`docs/screens/`を廃止し、`docs/pr-screenshots/`だけに一本化する**: 「今の画面がどうなっているか」を一覧するドキュメントが無くなってしまい、ADR 0004で解決した課題（今の仕様を一箇所で見たい）が再発する。
- **PR本文からスクリーンショットの埋め込みそのものをやめ、テキストでの確認内容のみにする**: レビュー時に見た目を確認できないというADR 0003の課題が再発するため見送った。

## 結果・影響

- `docs/screens/<画面名>.png`は「現在の仕様」であると同時に、直近のPR本文からも参照される画像になる。将来その画面が再び変更されて画像が上書きされると、過去にマージ済みのPRの本文に埋め込まれた画像も新しい見た目に置き換わって見える（そのPRをレビューした時点のスクリーンショットではなくなる）。これは意図した trade-off であり、正確な「レビュー当時の記録」が必要な場合は別途PRのコミット履歴やCIのアーティファクトを参照する必要がある。
- マージ前のPRプレビューでは、GitHubの相対リンク解決の制約により画像が表示されないことがある（詳細は「コンテキスト」参照）。必要であればPRの説明の中でその旨を一言添えるか、レビュー担当者にはリポジトリの`docs/screens/`を直接見てもらう。
- `docs/pr-screenshots/`はリポジトリに残らなくなり、ストレージの蓄積は起きなくなる。
