# ADR 0003: UIに影響する変更ではPR本文へのスクリーンショット埋め込みを必須にする

- ステータス: 廃止（後継: ADR 0006）
- 日付: 2026-09-13

> **注記（2026-09-13）**: `docs/pr-screenshots/pr-<PR番号>/`にPRごとのスクリーンショットを保存・蓄積する方式は、[ADR 0006](./0006-reference-docs-screens-in-pr-body-instead-of-archiving.md)により、`docs/screens/`（画面仕様書、ADR 0004で新設）の画像をそのままPR本文で参照する方式に置き換えられた。「UIに影響する変更ではPR本文にスクリーンショットを埋め込むこと自体を必須にする」という方針は継続する。以下は変更前の記録として残す。

## コンテキスト

これまで`fix-and-verify`スキルは、UIに影響する変更をコミットする前に`verify-front`スキルでスクリーンショットを撮影し、チャット上でユーザーに見せてOKをもらう運用だった。一方で、そのスクリーンショット自体をPull Requestの本文に残す手順は定義されておらず、「テスト内容」セクションにはテキストでの確認内容しか書かれていなかった。

レビュアー（人間）が後からPRを見返すとき、チャットでのやり取りは残っていないため、テキストの説明だけでは実際の見た目を確認できない。UIの変更はテキストより画像で見た方が圧倒的に伝わりやすく、レビューの手戻りを減らせる。

## 決定

UIの見た目・挙動に影響する変更を含むPRでは、`verify-front`スキルで撮影したスクリーンショットをPR本文（「テスト内容」セクション）にMarkdown画像として埋め込むことを必須にする。

- 保存場所: `docs/pr-screenshots/pr-<PR番号>/`配下にPNGを配置する。
- 手順: PR作成後、採番されたPR番号を使ってスクリーンショットを配置・コミット・pushし（既存PRに自動反映される）、`mcp__github__update_pull_request`でPR本文にMarkdown画像として埋め込む。
- 手順は`.claude/skills/commit-and-pr/SKILL.md`（5.1節）と`.claude/skills/fix-and-verify/SKILL.md`に反映した。
- スクリーンショットはレビューの証跡として扱い、マージ後も削除しない。

## 検討した代替案

- **チャット上での提示のみで済ませ、PR本文には反映しない**: 実装コストは最も低いが、レビュアーが後から見返せる記録が残らず、今回解決したい問題（レビュー時に見た目を確認できない）が解消されない。
- **GitHubの`user-images.githubusercontent.com`への画像アップロード経由でPR本文に埋め込む**: GitHubのWeb UIで手動ドラッグ&ドロップした場合に使われる方式だが、Web UIのセッションを前提とした非公開のアップロードエンドポイントであり、Claude Codeが持つGitHub APIアクセスからは利用できない。
- **PRごとにスクリーンショットを一時ブランチ・別リポジトリなど外部に置き、マージ後に削除する**: 参照の安定性やクリーンアップの手間が増え、複雑さに見合うメリットが薄いと判断した。リポジトリに残すコスト（PNG数十KB程度×PR数）は、このデモ用リポジトリの規模では許容範囲と判断した。

## 結果・影響

- UIに影響するPRでは、`commit-and-pr`スキルの手順が1ステップ増える（PR作成後にスクリーンショットを追加コミットし、本文を更新する）。
- `docs/pr-screenshots/`配下にファイルが蓄積し続ける。将来リポジトリサイズが問題になった場合は、保持期間や参照方法（外部ストレージへの移行など）を再検討する必要がある。
- ロジックのみでUIに影響しない変更では、この手順は不要（従来どおりテキストでの報告のみ）。
