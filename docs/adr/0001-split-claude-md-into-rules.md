# ADR 0001: プロジェクト指示をCLAUDE.mdと`.claude/rules/`に分割する

- ステータス: 承認
- 日付: 2026-09-06

## コンテキスト

`CLAUDE.md`に、コーディング規約・Git規約・ADR運用の指示・`docs/demo/`の注意書きなどが積み重なり、これらすべてがどのセッションでも常にコンテキストへ読み込まれる状態になっていた。Claude Codeには`.claude/rules/`という、指示をトピックごとのファイルに分割し、`paths`のfrontmatterを指定したファイルは該当パスのファイルを開いたときだけ読み込まれる仕組みが用意されている（[公式ドキュメント](https://code.claude.com/docs/ja/memory#organize-rules-with-claude/rules/)）。

## 決定

`CLAUDE.md`は、どのセッションでも常に前提となる概要（コマンド一覧、アーキテクチャの要点）のみを残す。それ以外の指示は`.claude/rules/`配下の個別ファイルに分割する。

- `front-code-style.md`（`paths: front/src/**/*`）… UI文言・スタイリング・コンポーネントのコーディング規約
- `git-conventions.md`（pathsなし、常時読み込み）… コミットメッセージの規約
- `demo-docs.md`（`paths: docs/demo/**`）… `docs/demo/`配下が勉強会用の架空データである旨の注意書き
- `adr-prompt.md`（pathsなし、常時読み込み）… 手戻りの大きい決定があった場合にADR化を提案する指示

## 検討した代替案

- **`CLAUDE.md`一枚に書き続ける**: 現状の分量ならまだ許容範囲だが、今後ルールが増えるたびに全セッションのコンテキスト消費が増え続ける。ルールが少ないうちに分割パターンを確立しておく方が、後からの移行より安価だと判断した。
- **`@path`インポート構文で`CLAUDE.md`から分割ファイルを読み込む**: ファイルの整理はできるが、インポートされたファイルは結局セッション開始時に全文読み込まれるため、コンテキスト削減の効果がない。`.claude/rules/`の`paths`スコープの方が実質的な効果がある。

## 結果・影響

- `front/src`以外の作業（docs編集、スキル追加など）では、フロントエンドのコーディング規約がコンテキストに乗らなくなる
- `docs/demo/`配下のファイルを実際に開いたときだけ、架空データである旨の注意が読み込まれる
- 今後プロジェクト指示を追加する際は、「常に必要か」「特定パスの作業でのみ必要か」を都度判断したうえで、`CLAUDE.md`と`.claude/rules/`のどちらに置くかを決める
