# ADR 0011: 「変更したら見直す記述」をdocs/doc-map.mdの対応表に集約し、Stop hookで未更新を知らせる

- ステータス: 承認
- 日付: 2026-11-03

## コンテキスト

コードやドキュメントを書き換えたあと、全体を見渡すと、大本の定義や関連するドキュメント（AGENTS.mdのアーキテクチャ要約、`docs/Architecture.md`、README、デモ台本など）が古いまま残っていることが多かった。

更新漏れを防ぐ仕組みはすでにあったが、次の抜けがあった。

- 「このファイルを変えたら、どの記述が古くなるか」という知識が、`design-docs`・`agent-config`・`demo-docs`ルール、`issue-create`スキル、`reviewer`サブエージェントに分散していた。
- ルールは`paths`で読み込まれるため、対象パス以外の変更（`app/components/`・`app/utils/`・`server/utils/`、シードデータ、`mcp-server/`、npmスクリプトなど）では、構成の説明を見直すきっかけがなかった。
- どれもエージェントが思い出せば守る「お願い」で、作業の終わりに機械的に気づかせる仕組みがなかった。

## 決定

- 「変更したパス → 見直す記述」の対応を`docs/doc-map.md`の表に1か所でまとめる。人とエージェントの両方が読み、hookも同じ表を機械的に読む。各ルール・`reviewer`は、この表を参照する形にする。
- 表の行には「きっかけ」を持たせる。`変更`はファイルの追加・変更・削除のすべてを、`追加・削除`は追加・削除・リネームだけを対象にする。構成の説明のように、中身の変更では古くならない記述で、通知が多くなりすぎないようにするため。
- Stop hook（`.claude/hooks/doc-sync-reminder.mjs`）を追加する。ターンの終わりに、ブランチの変更（mainとのmerge-baseからの差分、未コミットの変更、未追跡のファイル）を対応表と突き合わせる。変更したパスに当たる行があるのに、その行の「見直す記述」が変わっていなければ、exit 2でエージェントに見直しを促す。
- 通知は「見直しを促す」までにとどめ、更新を強制しない。更新不要と判断できるケースが多いため、同じセッションで同じ組み合わせは1回だけ通知する（記録は`.git/`配下）。`stop_hook_active`が立っているときは何もしない。

## 検討した代替案

- **ドキュメント内のパス参照が実在するかをチェックするlinter**: 試しに走らせたところ、実際に壊れた参照はほとんどなかった。古くなるのは主に記述の中身（構成の説明、手順、期待表示）なので、リネームしか検出できない方式では不十分だった。
- **`paths`付きのルールを増やす**: ファイルを開いたときにしか読み込まれず、変更した後に「関連する別ファイル」を思い出させる用途には合わない。分散がさらに進む。
- **更新しない限り終われないようにする（強制）**: 更新不要なケースでも何かを書き換えさせることになり、無意味な変更やループを招く。ADR 0008の方針どおり、強制は権限設定に限り、ここは「気づかせる」にとどめた。
- **定期的に全体を棚卸しするスキル**: 積もったズレの対策としては有効だが、まずは変更した直後に気づける仕組みを優先した。対応表はそのまま棚卸しにも使えるので、必要になったら追加する。

## 結果・影響

- コードを変えたセッションの終わりに、関連する記述の見直しが自動で促される。対応表に行を足せば、hook・ルール・レビューのすべてに反映される。
- 対応表自体の保守が必要になる。新しい依存関係に気づいたら表に行を追加する（`agent-config`ルール）。表に載っていない関係は検出されない。
- 長いブランチでは、そのセッションで触っていない過去のコミットの変更も対象になる。ただし通知はセッションごとに1回なので、作業の妨げにはなりにくい。
- 表のフォーマット（`## 対応表`見出しの下の4列の表、バッククォートで囲んだglob）をhookが解析しているため、表の形を変えるときはhookも合わせて直す必要がある。
