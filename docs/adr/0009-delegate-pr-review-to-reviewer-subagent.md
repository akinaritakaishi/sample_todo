# ADR 0009: PRレビューの差分チェックと分類はreviewerサブエージェントに任せる

- ステータス: 承認
- 日付: 2026-10-27

## コンテキスト

`pr-review`スキルはメインセッションのコンテキスト内で`code-review`スキルを使って差分をレビューしていた。実装したのと同じセッションでセルフレビューすると、実装時の前提や意図に引きずられた「甘いレビュー」になりやすく、差分の読み込みでメインセッションのコンテキストも消費する（Issue #34）。

## 決定

`.claude/agents/reviewer.md`にレビュー専任のサブエージェントを定義し、`pr-review`スキルの「差分のレビュー」「must/imo/nitsへの分類」を任せる。

- 使えるツールは読み取り系（Read・Grep・Glob）だけにし、編集・コミット・push・GitHubへの投稿はできないようにする
- サブエージェントはBashやGitHub APIを使えないため、`pr-review`スキル側でPRの差分とhead時点の変更ファイル全文をファイルに保存して渡す
- 実装の経緯や自分の見解は渡さず、差分とコード、PRのタイトル・本文だけを根拠にレビューさせる
- `learnings.md`の読み込みと分類基準はサブエージェントの定義に移す。レビューの提出・PRの監視・知見の蓄積・Approve判定（過去の指摘への返信状況の確認）はスキル側に残す

## 検討した代替案

- スキル内で「先入観を捨ててレビューすること」と指示するだけにする: 同じコンテキストのままなので効果が限られるため不採用
- サブエージェントにBashを与えて自分で`gh pr diff`を取得させる: 1つのツールで編集・コミットもできてしまい、「レビュー担当は書き込めない」ことを権限で保証できないため不採用

## 結果・影響

- `pr-review`の出力（`[レビュワー] **must:** ...`のインラインコメントと判定）は変わらない
- 材料の準備（差分とhead全文の保存）の手順が`pr-review`スキルに増える
- `code-review`スキルは`pr-review`からは使わなくなる。レビューの観点を増やしたいときは`reviewer.md`を更新する
