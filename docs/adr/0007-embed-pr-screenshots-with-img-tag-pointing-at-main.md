# ADR 0007: PR本文のスクリーンショットはmainブランチを指す`<img>`タグで埋め込む

- ステータス: 承認
- 日付: 2026-09-24

## コンテキスト

ADR 0006で、UIに影響する変更を含むPRでは`docs/screens/<画面名>.png`をPR本文にMarkdown画像（`![alt](docs/screens/<画面名>.png)`）として埋め込むことにした。

実際にPR #20・#21でこの手順どおりにPR本文を作成したところ、GitHub MCPツール（`create_pull_request`・`update_pull_request`）経由で登録した本文では、Markdown画像記法の先頭の`!`が落ち、`[alt](path)`というただのリンクとして保存されていた。本文をAPIで読み直して確認したもので、2つのPRで同じ現象が起きている。原因がGitHub側かMCPツール側かは特定できていない。

一方、同じ本文をHTMLの`<img>`タグで書くと、タグはそのまま保持されることを確認した。

また`<img>`タグの`src`に作業ブランチのURLを書くと、マージ後にブランチが削除された時点でリンク切れになる（PR #20のブランチはマージ直後に削除されていた）。

## 決定

- PR本文のスクリーンショットは、Markdown画像記法ではなく**HTMLの`<img>`タグ**で埋め込む。
- `src`は**`main`ブランチ**の`docs/screens/<画面名>.png`を指す絶対URL（`https://github.com/akinaritakaishi/sample_todo/blob/main/docs/screens/<画面名>.png?raw=true`）にする。
- 本文を登録したら読み直して、`<img>`タグが残っていることを確認する。
- ADR 0006の次の方針は変更しない。
  - PRごとのアーカイブは持たず、`docs/screens/`の「現在の仕様」を参照する。
  - デフォルトブランチの画像を参照するため、マージ前のPR本文には変更前の画像が表示されることを許容する。

手順は`.claude/skills/commit-and-pr/SKILL.md`（5.1節）と`.claude/rules/design-docs.md`に反映する。

## 検討した代替案

- **Markdown画像記法のまま、登録後に手で`!`を補う**: 原因が分からないため毎回崩れる可能性があり、登録のたびに直す手間がかかる。
- **作業ブランチ（またはコミットSHA）を指すURLにする**: マージ前から新しい画像が表示される利点はある。ただしブランチを指す場合はブランチ削除でリンク切れになる。コミットSHAを指す場合はリンク切れにならないが、ADR 0006の「`docs/screens/`の現在の仕様を参照する」方針から外れ、画像の更新後に参照先を毎回付け替える必要が出る。
- **画像をPRコメント等に直接アップロードする**: GitHub MCPツールからは画像ファイルをアップロードできないため採れない。

## 結果・影響

- PR本文の画像が確実に画像として表示されるようになる（マージ前は変更前の画像）。
- `src`にリポジトリ名とブランチ名（`main`）を含む絶対URLを書くため、リポジトリ名やデフォルトブランチ名を変更した場合は、スキルの例と過去PRの画像リンクが影響を受ける。
- マージ前のPRで最新の画像を確認したい場合は、レビュー担当者にPRの差分（`docs/screens/<画面名>.png`）を直接見てもらう。
