# PRレビュー・ループ（ワークフロー）

## 方針

このスキルは**手順の組み立てだけ**を担当します。各ステップの中身は、それぞれ単独でも使えるスキルに任せ、ここでは繰り返しません。

- `commit-and-pr` … コミット・push・PR作成
- `pr-review` … 差分のレビュー、must/imo/nitsのインラインコメント、Approve / Request changesの提出
- `fix-and-verify` … レビューコメント（またはIssue）を入力にしたコード修正・動作確認・既存PRへのpush・コメントへの返信

## 全体の流れ

```mermaid
flowchart TD
    A{PRは存在するか} -- なし/未コミットの変更あり --> B[commit-and-pr]
    A -- あり --> R
    B --> R[pr-review]
    R --> C{指摘はあるか}
    C -- なし(Approve) --> D[終了を報告]
    C -- あり --> G{サイクル上限(2回)に達したか}
    G -- 未達 --> F[fix-and-verify<br/>入力=今回のレビューコメント]
    F --> R
    G -- 達した --> H[残った指摘を報告し<br/>続行するかユーザーに確認]
```

## 各ステップ

1. **PRの用意**: 未コミットの変更がある、またはPRがまだない場合は`commit-and-pr`を呼ぶ。既存PRのレビューだけなら省略する。
2. **レビュー**: `pr-review`を呼ぶ。返ってきた判定と指摘一覧を受け取る。
3. **判定**
   - 指摘0件 → ループ終了。
   - 指摘あり（must/imo/nitsいずれも。ユーザーが「nitsは無視していい」等を指定した場合はそれに従う）→ 4へ。
4. **修正**: `fix-and-verify`を、入力を「手順2で提出されたレビューのコメント」として呼ぶ。修正・動作確認・既存PRへのpush・各コメントへの返信は`fix-and-verify`側の手順に従う。UIに影響する修正ではユーザーのOK待ちが入るが、これは`fix-and-verify`の核なので、ループ中でも省略しない。
5. pushが済んだら2に戻る（サイクル数を+1）。

## 終了条件

- `pr-review`で指摘0件になったら、その旨をユーザーに報告して終了する。
- 2サイクル（レビュー→修正を2回）実施しても指摘が残る場合は自動修正を打ち切り、残っている指摘一覧（must/imo/nits別）を報告したうえで「2サイクル実施しましたが、まだ指摘が残っています。続けますか？」とユーザーに確認する。無限ループを避ける安全装置なので、指示なしに3サイクル目へ進まない。

それ以外（サイクルの区切り）では逐一の確認は不要。何が起きたかを一言報告して次へ進む。

## 注意事項

- 各スキルの内部手順（レビュー観点、ラベルの基準、コミット規約、返信の書き方など）をこのファイルに書き足さないこと。変更は該当スキル側で行う。
- 最終的な承認・マージは人が行う（`pr-review`のApproveはAIによる一次判定）。
