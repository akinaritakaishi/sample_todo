# Claude Code向け設定（`.claude/`・CLAUDE.md）を編集するときのルール

- **お願いと強制を分ける**（ADR 0008）: 必ず守らせたい制約は`settings.json`の`permissions`で、それ以外の手順・規約はCLAUDE.md・rules・スキルに書く。denyを追加するときは、別のツールや書き方（Readとcat、フラグの順番など）で抜けられないかも確認する。
- **常時読み込むものは最小限に**（ADR 0001）: 特定のファイルを触るときだけ要るルールは`paths`付きのrulesにし、CLAUDE.mdに足さない。
- **スキル**: `SKILL.md`のfrontmatterは`name`と`description`。descriptionには「何をするか」と「どんな依頼で使うか（依頼文の例）」を書く。他のスキルと手順を重複させず、呼び出す・参照する形にする。
- **サブエージェント**: `tools`は役割に必要な最小限にする（`reviewer`は読み取り系のみ、ADR 0009）。
- **hook**: 「検査の失敗」（Claudeに直させたいもの）だけをexit 2で返し、ツール自体が動かない失敗はexit 1などブロックしない形にする。パスの判定はWindows（バックスラッシュ区切り）でも動くようにする。
- **パス・ツール名は実在を確認して書く**: 存在しないファイルやツールを指すと、読んだセッションが古い手順で動いてしまう。GitHub MCPツールなど環境によって無いツールに頼る手順には、代わりの手段（`gh` CLIなど）を書く。
- **二次的な記述も直す**: スキル・ルール・ADRで手順を変えたら、同じ内容を書いている他の場所（CLAUDE.mdの「Claude Code向け設定の構成」、README、他のスキル、`docs/`）をキーワードでgrepして揃える。スキル・サブエージェント・hookを追加・削除したら、CLAUDE.mdの「Claude Code向け設定の構成」とREADMEの「Claude Code向け設定」も更新する。
- 後から覆すと手戻りが大きい変更（権限の方針、スキル間の責務の分担など）はADRを提案する（`adr-prompt`ルール）。
